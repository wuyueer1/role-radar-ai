# RoleRadar AI：三分钟面试演示

## 一句话定位

RoleRadar AI 把持续更新的真实 AI 岗位供给，转成针对候选人的可解释机会排序；无需账号，粘贴 JD 也不会上传。

## 0:00–0:25｜先讲产品发现，而不是先讲技术

“第一版作品做的是一张静态职业路径图。它看起来完整，但没有解决求职者每天真正面对的问题：市场上现在有哪些岗位，我为什么应该投，以及缺什么证据。这个失败让我把核心用户任务从‘展示简历’改成‘基于真实岗位做行动决策’。”

动作：打开公开首页，指出没有 OpenAI、GitHub 或其他账号门槛。

面试官应看到：RoleRadar AI 品牌、数据更新时间、revision、快照状态和“分析一条 JD”。

## 0:25–0:55｜证明数据是真的、失败边界也是真的

“页面不是抓一张静态列表。数据管线先探测两个经过审查的官方公开招聘源，再做 schema 校验、归一化、去重和原子发布。某个来源失败时，不会把坏数据覆盖到线上，而是保留 last-good 快照。”

动作：点击“查看数据源状态”。

面试官应看到：Anthropic Greenhouse、Binance Lever、各自抓取时间、原始岗位数和健康状态。

补充边界：“BOSS 直聘和猎聘受平台限制，我没有把高风险抓取包装成实时 API；这两类链接会提示复制 JD 正文。”

## 0:55–1:20｜读市场，而不是读一份简历

“顶部四个指标回答供给规模、岗位流动、最大角色簇和增长技能。所有趋势都基于完整快照周期，而且页面明确写着‘只代表已接入来源’。”

动作：滚到市场脉搏，指出当前岗位数、最大角色簇和增长技能。

可追问：为什么不显示全市场占比？

回答：“数据源覆盖不完整时，精确全市场占比会制造虚假确定性，所以我只展示可追溯样本内统计。”

## 1:20–1:50｜从筛选进入可解释匹配

“筛选条件会写入 URL，面试官可以分享同一个视图。每个岗位的匹配不是一个黑盒数字，而是技能、证据、语义、角色邻近和明确约束五部分。”

动作：地点切到“全部地点”，角色选“AI 产品”，打开一条岗位。

面试官应看到：岗位要求与候选人证据配对、五项分量、优势、待补证据、分析模式/版本、抓取时间和真实投递链接。

关键句：“匹配分用于相对排序，不是录用概率。”

## 1:50–2:10｜用岗位簇讲清楚市场结构

“岗位标签不是孤立类别。节点大小是岗位数，颜色是 7 日变化，连线是岗位簇 Top skills 的 Jaccard 相似度。点击节点会直接筛选真实岗位。”

动作：点击“AI 产品岗位簇”。

面试官应看到：筛选状态反馈和对应岗位列表。

可追问：为什么用 Jaccard？

回答：“它简单、可复算、适合解释共同技能；如果数据规模和技能质量提高，可以替换为图嵌入，但当前阶段不需要制造复杂度。”

## 2:10–2:40｜演示浏览器本地 JD 分析

“用户经常从不同平台拿到一条 JD。这里可以直接粘贴文本，相关度与五分量全部在浏览器内计算，不上传、不持久化。”

动作：点击“分析一条 JD”→“填入示例”→“开始本地分析”。

面试官应看到：本地即时分析、匹配分、五分量、可证明优势和面试前补强。

关键句：“输入不写入 localStorage / sessionStorage，也没有远程模型调用或分析埋点。”

## 2:40–3:00｜收束 AI、降级与工程价值

“定时管线优先用固定版本的多语言 E5 做岗位池内语义排序；环境不可用时回退到具名的 TF-IDF 规则，界面会诚实显示模式。Service Worker 只缓存成功、非 opaque 的响应，并保留最后一份结构有效的 JSON，所以面试现场断网刷新仍能继续。”

收尾：“这个作品最想展示的不是‘我用了一个模型’，而是我能从用户任务出发，把真实数据、AI 方法、可解释性、隐私和交付可靠性做成一个完整产品。”

## 常见追问速答

- 为什么只有两个来源？先把条款清晰、可复现、可监控的官方源做好，再扩展 adapter；来源数不是核心 KPI，可信更新才是。
- 为什么不是实时到秒？招聘决策不需要秒级；4 小时刷新能降低来源压力，也符合面试作品的成本与可靠性目标。
- 为什么 E5 失败还能发布？可以回退，但模式与版本必须公开；probe、schema、测试或 build 失败则禁止覆盖 last-good 和部署。
- 如何扩展到更多公司？在 source registry 中新增经过审查的 Greenhouse/Lever board，adapter 契约和 schema 不变。
- 如何避免“AI 分数权威感”？公开权重、显示分量、配对原文证据、列出缺口和阻断条件，并明确不是录用概率。
